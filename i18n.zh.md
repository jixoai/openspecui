# OpenSpecUI Chinese terminology

| English term                        | Canonical Chinese term  | Meaning                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenSpec root                       | OpenSpec 规划根         | One writable `openspec/` planning tree selected for a command.                                                                                                                                                                                                                                                                     |
| project root                        | 项目规划根              | An OpenSpec root colocated with a code repository.                                                                                                                                                                                                                                                                                 |
| Store                               | 规划仓库                | A registered OpenSpec root with Store identity; normally standalone Git, but an existing nested root can be promoted without its own `.git`.                                                                                                                                                                                       |
| Store registry                      | 本机 Store 注册表       | Per-user/per-machine mapping from Store id to checkout path, shared across projects by default; its data root can be isolated with `XDG_DATA_HOME`.                                                                                                                                                                                |
| declared Store                      | 外置规划指针            | A config-only code repository's `store:` declaration that redirects root selection.                                                                                                                                                                                                                                                |
| Reference                           | 只读规划引用            | A declaration that adds another Store's specs to instructions without changing the writable root.                                                                                                                                                                                                                                  |
| Context                             | 工作上下文              | The current root plus its available referenced Stores, derived from declarations.                                                                                                                                                                                                                                                  |
| Workset                             | 个人工作集              | A local named set of folders opened together; it carries no planning semantics.                                                                                                                                                                                                                                                    |
| root selection                      | 规划根选择              | The ordered procedure that decides where a command acts.                                                                                                                                                                                                                                                                           |
| multi-root planning                 | 多规划根协作            | Planning across independently owned roots without introducing a package graph.                                                                                                                                                                                                                                                     |
| OpenSpec data home                  | OpenSpec 用户数据根     | The single `${XDG_DATA_HOME}/openspec` tree containing Store registry, Worksets, and user schema overrides.                                                                                                                                                                                                                        |
| OpenSpec data scope                 | OpenSpec 数据域         | The runtime selection of one OpenSpec data home; scopes replace rather than overlay each other.                                                                                                                                                                                                                                    |
| launch project                      | 启动项目                | The code project used to start one OpenSpecUI backend session.                                                                                                                                                                                                                                                                     |
| Root Context                        | 根上下文                | The shared reactive projection of launch project, CLI-selected planning root, direct References, CLI evidence, and inherited data scope.                                                                                                                                                                                           |
| workflow target                     | 工作流目标              | The launch project, selected planning root, root source, Store id/selector, References, and root evidence fixed for one action.                                                                                                                                                                                                    |
| workflow action evidence            | 工作流操作证据          | The command-specific Status or Instructions result retained with parsed data, raw output, paths, diagnostics, and exit status.                                                                                                                                                                                                     |
| workflow hook v2                    | 工作流 Hook v2          | The breaking hook contract whose context carries an explicit workflow target instead of ambiguous `projectDir`.                                                                                                                                                                                                                    |
| Root action gate                    | 根操作门禁              | The shared readiness rule that unlocks root-dependent actions only for a current ready Root Context.                                                                                                                                                                                                                               |
| stale Root Context                  | 过期根上下文            | The last successful Root Context retained for display during refresh/failure; it is informative but cannot authorize a new action.                                                                                                                                                                                                 |
| Project Binding                     | 项目绑定                | Launch-project `store:` and `references:` declarations plus the resulting Root Context preview; it does not own active-root schema/rules.                                                                                                                                                                                          |
| Active Root Config                  | 当前规划根配置          | Schema, context, and rules stored in the CLI-selected writable planning root; an existing empty file remains distinct from an absent file.                                                                                                                                                                                         |
| Environment Global Config           | 环境全局配置            | Profile, delivery, workflows, and other OpenSpec global config selected by the backend runtime environment rather than one project.                                                                                                                                                                                                |
| Config readiness gate               | 配置就绪门禁            | The shared Root Context gate that keeps Config root mutations locked during loading, stale refresh, transport failure, or CLI-owned error.                                                                                                                                                                                         |
| shared Store consequence            | 共享 Store 影响         | An objective notice that an external Store-backed root is observed by other projects resolving the same Store; it is not a machine-wide project inventory.                                                                                                                                                                         |
| projection refresh lock             | 投影刷新锁              | A loading lock that spans the asynchronous subscription rebind until the replacement CLI projection arrives.                                                                                                                                                                                                                       |
| authoritative projection wait       | 权威投影等待            | A correctness-first wait while a route or action has stale/display data but no current subscription or Root-generation authority. It must not be presented as current success, but presentation need not discard usable stale content.                                                                                             |
| navigation preparation wait         | 导航预取等待            | The bounded query/prefetch phase that currently runs before a detail View Transition commits route navigation; it improves transition continuity but directly adds perceived navigation latency.                                                                                                                                   |
| interaction phase sample            | 交互阶段样本            | One bounded in-memory timing record from a single production coordinator. It measures named local phases but does not infer causality across independent subscriptions, Root resolution, or transports.                                                                                                                            |
| latest navigation request           | 最新导航请求            | The newest requested navigation in one route area. It is request provenance, not proof of the current Router location or DOM; superseded attempts retain their own late-effect evidence without reclaiming this identity.                                                                                                          |
| route update issued                 | 路由更新已发出          | The exact point at which the synchronous navigation update callback returns. A discarded Router navigation Promise means this fact does not prove Router completion or DOM commit.                                                                                                                                                 |
| artificial mount gate               | 人工挂载门闩            | A local first-frame Loading state that observes no network, subscription, Router, View Transition, or data-readiness fact. Settings and Archive historically owned separate instances; remove each only at its route while retaining real loading, error, updating, and authority topology.                                        |
| first-render draft authority        | 首帧草稿权威            | When a current cached configuration is already available, writable local draft state initializes from that value before effects. A default draft that is corrected later cannot authorize an immediate Save.                                                                                                                       |
| field-value draft synchronization   | 字段值草稿同步          | A local draft follows an actual upstream field-value change, not replacement identity of the enclosing parsed Config object. Equal emissions preserve dirty local edits; changed fields replace only their corresponding drafts.                                                                                                   |
| projection updating signal          | 投影更新信号            | An explicit subscription lifecycle fact that a retained projection is being recomputed or rebound. A component-only mock of `data + isLoading` cannot substitute for a production signal from the shared subscription owner.                                                                                                       |
| recompute-started                   | 重算已开始              | A subscription-local lifecycle event emitted after this ReactiveContext consumes a dependency wake and confirms it is not aborted, but before the replacement task executes. It is not a filesystem invalidation or WebSocket connection-state alias.                                                                              |
| reactive subscription retirement    | 响应式订阅清退          | Server-owned unsubscribe cleanup that aborts the underlying ReactiveContext stream and removes its tracked dependencies. Observer no-delivery alone does not prove this owner release.                                                                                                                                             |
| effective workflow default          | 有效工作流默认集        | The workflow set OpenSpec CLI applies from profile semantics; the core profile always uses the full core set regardless of raw `workflows` presence or content.                                                                                                                                                                    |
| config file presence                | 配置文件存在性          | The explicit `exists` fact for a config file; it is independent from whether the file content is empty.                                                                                                                                                                                                                            |
| Code repository                     | 代码仓库                | The Git repository containing the launch project; it is the explicit default scope for project Git operations.                                                                                                                                                                                                                     |
| Planning repository                 | 规划根 Git 仓库         | A distinct Git repository containing the CLI-selected planning root; it is absent when both roots share one Git identity.                                                                                                                                                                                                          |
| Git repository scope                | Git 仓库作用域          | The explicit `code` or `planning` target carried by Git queries, cache keys, routes, worktrees, and mutations.                                                                                                                                                                                                                     |
| Git repository identity             | Git 仓库身份            | Canonical Git worktree top-level plus common directory; path inequality alone does not create a second repository scope.                                                                                                                                                                                                           |
| Git repository binding token        | Git 仓库绑定令牌        | Backend-issued opaque epoch for one current Code/Planning binding; it binds Git requests and caches across Root transitions but grants no permission.                                                                                                                                                                              |
| Code binding continuity             | 代码绑定连续性          | Launch-owned Code scope discovery and operations remain usable while Planning-root resolution is pending or failing.                                                                                                                                                                                                               |
| Git handoff provenance              | Git 交接来源凭证        | The origin binding token carried through list/detail handoff and View-Transition preparation; a mismatched token invalidates the handoff instead of relabeling it.                                                                                                                                                                 |
| Git handoff entity provenance       | Git 交接实体凭证        | The handoff `entityId` must match the target commit or working-tree selector in addition to the Git family and origin binding token; same-binding but different-entity state is stale presentation.                                                                                                                                |
| Planning binding state              | 规划仓库绑定状态        | A typed `resolving`/`settled` state distinguishes an unresolved Planning binding from a settled absence or distinct repository; `resolving` cannot carry a Planning descriptor.                                                                                                                                                    |
| Git binding failure evidence        | Git 绑定失败证据        | Objective error provenance from Planning owner or Git identity resolution; it must not be presented as a settled same-repository or unavailable-Planning conclusion.                                                                                                                                                               |
| 6.11 decomposition gate             | 6.11 分解决策闸门       | The review state that keeps Git delivery, Binding settlement, reactive readiness, and browser evidence separate until the owner selects one package.                                                                                                                                                                               |
| Binding settlement contract         | 绑定结算合同            | The explicit choice between awaiting the full Planning-root transition and resolving after the launch binding write with typed convergence evidence.                                                                                                                                                                               |
| Project Binding repair path         | 项目绑定修复通道        | Launch-owned Store/Reference controls that remain usable while Root Context is stale or errored; they are not a Planning-root mutation authority.                                                                                                                                                                                  |
| binding draft generation            | 绑定草稿世代            | The identity of the draft associated with one completed launch write; a later user edit retires that pending generation so an old Root emission cannot clear the newer draft.                                                                                                                                                      |
| reactive readiness contract         | 响应式就绪合同          | The explicit choice between treating Offline WebSocket as locked/unavailable and requiring a non-WebSocket readiness fallback.                                                                                                                                                                                                     |
| Live status truth                   | 实时状态真值            | The connection indicator derived from the current transport lifecycle plus a current system emission; retained project metadata cannot keep `Live` green while the WebSocket is reconnecting or closed.                                                                                                                            |
| fixture/setup blocker               | 夹具/环境阻塞           | A bounded test-environment failure that does not prove a production defect and must be recorded once rather than retried indefinitely.                                                                                                                                                                                             |
| final browser acceptance            | 最终浏览器验收          | The owner's manual end-to-end walkthrough and acceptance. Agent-run Vitest and basic component-level Playwright fixtures may prepare evidence but never replace or claim this acceptance.                                                                                                                                          |
| tool artifact scope                 | 工具产物作用域          | The physical owner reported by upstream OpenSpec: project detection, skills, and ordinary commands belong to the Launch project, while Codex commands belong to the runtime environment under `${CODEX_HOME:-~/.codex}/prompts`.                                                                                                   |
| Settings OpenSpec diagnostics       | 设置页 OpenSpec 诊断    | Read-only composition of Root Context CLI/root facts, runtime-environment profile/delivery, and physically scoped tool-delivery state. Installer settlement retires runner cache before Root invalidation; editing stays in Config, diagnostics and initialization remain separate, and final browser acceptance stays owner-only. |
| production owner evidence           | 真实所有者证据          | A checked test that crosses the production composition and mutation owner named by the contract. A hand-authored downstream callback is characterization evidence and cannot prove the upstream owner.                                                                                                                             |
| presentation lock                   | 呈现锁                  | A disabled visual interaction state. It is not automatically a semantic mutation guard; the production contract must state whether forced or alternate public events can still reach the payload owner.                                                                                                                            |
| semantic dispatch guard             | 语义提交守卫            | The production check that rejects stale or invalid payloads before the mutation owner is called, independently of how the control is rendered.                                                                                                                                                                                     |
| guard reachability                  | 守卫可达性              | Whether a real production event can reach the guard under test. A downstream guard hidden behind an earlier hard guard cannot supply a route-level mutation red unless the product contract intentionally separates those responsibilities.                                                                                        |
| generation-owned dispatch instance  | generation 所属提交实例 | A terminal-dispatch subtree whose dialog, preset payload, and expected Root generation belong to one Root identity. A true identity change retires the prior subtree during reconciliation; a same-generation observation refresh preserves it.                                                                                    |
| batched-away transition             | 被批处理消除的过渡      | An intermediate loading/disabled state that never becomes a committed render because asynchronous updates settle in one React batch. A passive effect cannot be the only correctness boundary for state that must retire on the identity change itself.                                                                            |
| disabled-listener suppression       | 禁用监听器抑制          | React suppresses an intrinsic disabled control's event listener from committed props, even if a test removes only the DOM attribute. The resulting public event cannot reach a downstream semantic guard and must not be cited as mutation-resistant owner evidence.                                                               |
| form-submit owner                   | 表单提交所有者          | The production `form onSubmit` boundary that performs the final freshness check immediately before a mutation owner. A disabled submit button is only presentation and cannot replace this guard.                                                                                                                                  |
| Dashboard Git snapshot provenance   | 仪表盘 Git 快照来源凭证 | The Code binding token captured atomically with Dashboard Git entries; a snapshot from backend binding A cannot be relabeled with a freshly queried binding B.                                                                                                                                                                     |
| Git identity failure classification | Git 身份失败分类        | Only explicit canonical `not a git repository` evidence may settle-null; unknown, empty, permission, executable, I/O, or canonicalization failures remain failure evidence, and Code failures are not Planning failures.                                                                                                           |
| stale subscription projection       | 过期订阅投影            | Cached data retained while a subscription is loading or errored; it is display-only and cannot authorize Dashboard snapshot rendering, GitRoute/GitView actions, or Git handoff.                                                                                                                                                   |
| reconnecting scope projection       | 重连中的作用域投影      | A cached Git scope retained while a replacement subscription has not emitted; Dashboard, GitRoute, and GitView queries/actions remain locked until the replacement is current, even when no error has arrived yet.                                                                                                                 |
| Git transport authority             | Git 传输权威状态        | The tRPC subscription connection lifecycle; cached Git data remains non-authoritative through connecting/pending/error and becomes current only after replacement data is emitted.                                                                                                                                                 |
| subscription generation             | 订阅世代                | The active effect/transport generation that owns one Git projection; callbacks and loaders from a retired generation cannot mutate state or cache.                                                                                                                                                                                 |
| terminal subscription evidence      | 订阅终止证据            | `onError`, `onStopped`, or `onComplete` evidence that revokes cached Git authority until replacement `onData`; later transport notifications cannot erase the terminal diagnostic.                                                                                                                                                 |
| snapshot provenance                 | 快照来源证明            | The binding token captured with the rendered Dashboard Git snapshot and submitted unchanged by delayed actions; a later lookup cannot relabel the intent.                                                                                                                                                                          |
| observed-token mutation             | 观察令牌绑定操作        | A Dashboard or Git action carries the binding token observed with the rendered source; it never queries a newer token at execution time to relabel stale intent.                                                                                                                                                                   |
| Code binding owner                  | 代码绑定所有者          | The backend/Launch-scoped owner of the stable Code token, separate from the replaceable Planning-root manager and shared by Git binding plus Dashboard provenance.                                                                                                                                                                 |
| static Git projection               | 静态 Git 投影           | A typed unavailable projection with no live binding token; static mode cannot submit it as a live Git RPC provenance.                                                                                                                                                                                                              |
| Dashboard planning metrics          | 仪表盘规划指标          | Spec, Change, task, and workflow metrics read only from the CLI-selected planning root.                                                                                                                                                                                                                                            |
| Reference evidence                  | 引用证据                | Direct Store identities and CLI diagnostic counts shown without inferring health, ownership, or machine-wide completeness.                                                                                                                                                                                                         |
| degraded Reference warning          | 引用降级告警            | Non-fatal CLI evidence for a missing or unhealthy Reference; it remains visible without blocking a successfully resolved writable root.                                                                                                                                                                                            |
| Code Git snapshot                   | 代码仓库 Git 快照       | Dashboard Git activity from the Launch code repository, displayed independently from an optional distinct Planning repository.                                                                                                                                                                                                     |
| terminal cwd target                 | 终端工作目录目标        | The semantic `launch-project` or `planning-root` choice submitted by a client; the backend, not the browser, resolves its absolute path.                                                                                                                                                                                           |
| initial cwd                         | 初始工作目录            | The server-resolved absolute path where a PTY was spawned, retained with its semantic target across create, list, and reconnect.                                                                                                                                                                                                   |
| PTY slow-client isolation           | PTY 慢客户端隔离        | Per-WebSocket byte bounds terminate only a lagging PTY socket before its send queue can starve the shared Server event loop; the PTY process survives for reconnect and bounded replay.                                                                                                                                            |
| direct argv Agent spawn             | Agent argv 直启         | A configured Codex/Claude/Gemini invocation is passed to `node-pty` as an executable plus argument vector, instead of being typed as one long command into a newly created interactive shell.                                                                                                                                      |

| Agent terminal reveal               | Agent 终端揭示          | After Create or Send activates its target session, navigation reveals `/terminal` in its owning area. | root-dependent mutation             | 规划根依赖型变更        | A Spec, Change, task, archive, artifact, schema, or active-config write whose only filesystem owner is the current CLI-selected planning root.                                                                                                                                                                                     |

| envUri                              | 环境 URI                | Backend-issued opaque URI identifying one backend-host and OpenSpec-data-home combination; it is an identity, not an API locator.                                                                                                                                                                                                  |

| dependency ownership                | 响应式依赖归属          | Every subscription collects its own file dependencies inside its `ReactiveContext`; awaiting another context's shared read Promise does not transfer them.                                                                                                                                                                         |
| static Reference export             | 静态引用物化            | The explicit `7.*` export step that places consented direct Referenced Specs into a snapshot; before it exists, static Referenced Search is objectively empty.                                                                                                                                                                     |
