# OpenSpecUI Chinese terminology

| English term                 | Canonical Chinese term | Meaning                                                                                                                                                    |
| ---------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenSpec root                | OpenSpec 规划根        | One writable `openspec/` planning tree selected for a command.                                                                                             |
| project root                 | 项目规划根             | An OpenSpec root colocated with a code repository.                                                                                                         |
| Store                        | 规划仓库               | A registered OpenSpec root with Store identity; normally standalone Git, but an existing nested root can be promoted without its own `.git`.               |
| Store registry               | 本机 Store 注册表      | Per-user/per-machine mapping from Store id to checkout path, shared across projects by default; its data root can be isolated with `XDG_DATA_HOME`.        |
| declared Store               | 外置规划指针           | A config-only code repository's `store:` declaration that redirects root selection.                                                                        |
| Reference                    | 只读规划引用           | A declaration that adds another Store's specs to instructions without changing the writable root.                                                          |
| Context                      | 工作上下文             | The current root plus its available referenced Stores, derived from declarations.                                                                          |
| Workset                      | 个人工作集             | A local named set of folders opened together; it carries no planning semantics.                                                                            |
| root selection               | 规划根选择             | The ordered procedure that decides where a command acts.                                                                                                   |
| multi-root planning          | 多规划根协作           | Planning across independently owned roots without introducing a package graph.                                                                             |
| OpenSpec data home           | OpenSpec 用户数据根    | The single `${XDG_DATA_HOME}/openspec` tree containing Store registry, Worksets, and user schema overrides.                                                |
| OpenSpec data scope          | OpenSpec 数据域        | The runtime selection of one OpenSpec data home; scopes replace rather than overlay each other.                                                            |
| launch project               | 启动项目               | The code project used to start one OpenSpecUI backend session.                                                                                             |
| Root Context                 | 根上下文               | The shared reactive projection of launch project, CLI-selected planning root, direct References, CLI evidence, and inherited data scope.                   |
| workflow target              | 工作流目标             | The launch project, selected planning root, root source, Store id/selector, References, and root evidence fixed for one action.                            |
| workflow action evidence     | 工作流操作证据         | The command-specific Status or Instructions result retained with parsed data, raw output, paths, diagnostics, and exit status.                             |
| workflow hook v2             | 工作流 Hook v2         | The breaking hook contract whose context carries an explicit workflow target instead of ambiguous `projectDir`.                                            |
| Root action gate             | 根操作门禁             | The shared readiness rule that unlocks root-dependent actions only for a current ready Root Context.                                                       |
| stale Root Context           | 过期根上下文           | The last successful Root Context retained for display during refresh/failure; it is informative but cannot authorize a new action.                         |
| Project Binding              | 项目绑定               | Launch-project `store:` and `references:` declarations plus the resulting Root Context preview; it does not own active-root schema/rules.                  |
| Active Root Config           | 当前规划根配置         | Schema, context, and rules stored in the CLI-selected writable planning root; an existing empty file remains distinct from an absent file.                 |
| Environment Global Config    | 环境全局配置           | Profile, delivery, workflows, and other OpenSpec global config selected by the backend runtime environment rather than one project.                        |
| Config readiness gate        | 配置就绪门禁           | The shared Root Context gate that keeps Config root mutations locked during loading, stale refresh, transport failure, or CLI-owned error.                 |
| shared Store consequence     | 共享 Store 影响        | An objective notice that an external Store-backed root is observed by other projects resolving the same Store; it is not a machine-wide project inventory. |
| config file presence         | 配置文件存在性         | The explicit `exists` fact for a config file; it is independent from whether the file content is empty.                                                    |
| Code repository              | 代码仓库               | The Git repository containing the launch project; it is the explicit default scope for project Git operations.                                             |
| Planning repository          | 规划根 Git 仓库        | A distinct Git repository containing the CLI-selected planning root; it is absent when both roots share one Git identity.                                  |
| Git repository scope         | Git 仓库作用域         | The explicit `code` or `planning` target carried by Git queries, cache keys, routes, worktrees, and mutations.                                             |
| Git repository identity      | Git 仓库身份           | Canonical Git worktree top-level plus common directory; path inequality alone does not create a second repository scope.                                   |
| Dashboard planning metrics   | 仪表盘规划指标         | Spec, Change, task, and workflow metrics read only from the CLI-selected planning root.                                                                    |
| Reference evidence           | 引用证据               | Direct Store identities and CLI diagnostic counts shown without inferring health, ownership, or machine-wide completeness.                                 |
| degraded Reference warning   | 引用降级告警           | Non-fatal CLI evidence for a missing or unhealthy Reference; it remains visible without blocking a successfully resolved writable root.                    |
| Code Git snapshot            | 代码仓库 Git 快照      | Dashboard Git activity from the Launch code repository, displayed independently from an optional distinct Planning repository.                             |
| terminal cwd target          | 终端工作目录目标       | The semantic `launch-project` or `planning-root` choice submitted by a client; the backend, not the browser, resolves its absolute path.                   |
| initial cwd                  | 初始工作目录           | The server-resolved absolute path where a PTY was spawned, retained with its semantic target across create, list, and reconnect.                           |
| root-dependent mutation      | 规划根依赖型变更       | A Spec, Change, task, archive, artifact, schema, or active-config write whose only filesystem owner is the current CLI-selected planning root.             |
| planning root                | 规划根                 | The single writable OpenSpec root selected by the CLI for the current operation.                                                                           |
| project workspace            | 项目工作台             | The WebUI surface for one launch project and its resolved planning context.                                                                                |
| runtime environment          | OpenSpec 运行环境      | One backend execution environment sharing a CLI installation, process environment, OpenSpec data scope, and Store registry.                                |
| Store Manager                | Store 管理器           | The App-native surface that administers Stores through one selected OpenSpec runtime environment.                                                          |
| envUri                       | 环境 URI               | Backend-issued opaque URI identifying one backend-host and OpenSpec-data-home combination; it is an identity, not an API locator.                          |
| Backend Access Gate          | 后端访问门禁           | Optional single-shared-credential guard for one whole backend; it is not a user, role, ACL, or permission system.                                          |
| capability                   | 协议能力               | A declaration that a backend implements one hosted-protocol feature; it carries no authorization meaning.                                                  |
| objective projection         | 客观投影               | A UI rendering of upstream OpenSpec facts and diagnostics that preserves uncertainty and does not invent domain conclusions.                               |
| observed context             | 已观察上下文           | Root/Reference relationships reported by currently connected project backends; it is never a complete machine-wide reverse index.                          |
| reactive kernel              | 响应式内核             | OpenSpecUI's multi-root observer that pushes environment-scoped invalidations so every client can pull fresh CLI-owned projections.                        |
| observation root             | 观察根                 | A filesystem root currently covered by one physical watcher; path subscriptions bind to the deepest active containing root.                                |
| observation root lease       | 观察根租约             | A reference-counted ownership claim that keeps one observation root alive until its final owner releases it.                                               |
| observation environment      | 响应式观察环境         | The backend-runtime owner of a dynamic set of Launch, Planning, data-home, and Store observation-root leases.                                              |
| runtime invalidation facet   | 运行时失效分面         | A named projection identity plus monotonic generation that tells consumers to pull fresh truth without carrying the truth itself.                          |
| Store root reconciliation    | Store 根调和           | The CLI-list-driven acquire/replace/release procedure that keeps observed Store root leases aligned with successful registry truth.                        |
| project-root invalidation    | 项目根失效映射         | The normalized, reference-counted mapping from Launch/Planning root changes to `project` and `context` facets, separate from physical watcher ownership.   |
| CLI mutation settlement      | CLI 变更结算           | The terminal or indeterminate boundary that invalidates affected facets before preserving and delivering the original CLI outcome.                         |
| invalidation push            | 失效推送               | An identity-only `facet + generation` message that tells clients to pull fresh CLI-owned projection data.                                                  |
| invalidation coalescing      | 失效合并               | Per-subscriber batching that retains only each facet's latest generation within one microtask while generations still advance synchronously.               |
| bounded observation fallback | 有界观察回退           | One environment-owned periodic check that emits pull signals only while data-home, Store-root, or watcher observation is degraded.                         |
| reactive teardown            | 响应式环境清退         | The ordered async release of fallback work, logical root leases, path subscriptions, and physical watchers for one backend runtime.                        |
| reactive convergence matrix  | 响应式收敛矩阵         | The two-client acceptance set for external edits, registry changes, concurrent settlement, reconnect, root disappearance, and teardown.                    |
| indeterminate                | 结果不确定             | A mutation whose terminal CLI result cannot be recovered; it is neither fabricated failure nor cancellation.                                               |
| tracked task progress        | 正式任务进度           | Progress from the one artifact selected by OpenSpec `apply.tracks`; it drives workflow task state.                                                         |
| document checklist summary   | 文档检查项统计         | Secondary counts across schema documents, retained for planning analysis but excluded from workflow decisions.                                             |
| apply instruction progress   | Apply 指令进度         | Raw task progress reported by `openspec instructions apply`, attributed separately when upstream paths diverge.                                            |
| tracked artifact glob        | 正式任务制品通配模式   | The selected artifact output pattern expanded for formal workflow task truth; unrelated schema documents are excluded.                                     |
| tracked task location        | 正式任务位置           | The exact tracked Markdown `filePath` plus file-local 1-based checkbox index used by a guarded task mutation.                                              |
| canonical OpenSpec entity id | 规范 OpenSpec 实体标识 | A non-empty single path segment used for a filesystem-backed Spec or Change; path syntax is rejected before any read or mutation.                          |
| entity-relative path         | 实体内相对路径         | A file or glob confined to one entity root; absolute and parent-traversal paths are rejected before filesystem access.                                     |
| no-tasks                     | 无任务态               | The formal state for `0/0`; it is distinct from completion and says nothing about archive readiness.                                                       |
| workflow-complete            | 工作流完成态           | Status/artifact and formal tracked-task completion evidence; it is not an archive-readiness conclusion.                                                    |
| Change CLI context           | Change CLI 上下文      | CLI-authored planning home, Change root, artifact paths, action context, next steps, and root source retained by live Change Status.                       |
| strict archive preflight     | 严格归档预检           | One Server-owned, single-root `validate --strict` gate before archive; failure diagnostics terminate without archive or a synthesized bypass retry.        |
| public CLI execution gate    | 公共 CLI 执行门禁      | Shared Server policy for dedicated buffered/streamed OpenSpec RPCs; Archive remains dedicated and arbitrary process launch is excluded.                    |
| physical/reactive writer     | 物理响应式写入所有者   | Owner used by every direct write/create/delete surface: physical confinement, disk mutation, then reactive settlement.                                     |
| active-root replacement      | 当前规划根替换         | Root Context-driven switch that retires old Planning-root services, leases, and previews before exposing the new root.                                     |
| active-root operation lease  | 当前规划根操作租约     | Manager-owned lifetime that lets an admitted operation finish before root replacement and prevents retired service handles from mutating the old root.     |
| stream cancellation request  | 流取消请求             | A request to terminate a child process; it is not settlement and cannot release a Planning-root operation lease before process close.                      |
| stream settlement            | 流结算                 | A child `close` or startup outcome proving no child exists; only this confirmed boundary may release a Planning-root operation lease.                      |
| stream termination failure   | 流终止确认失败         | A bounded failure to confirm direct-child close after forced termination. It keeps the old root blocked, but must deliver exactly one terminal error.      |
| Core child ownership slot    | Core 子进程所有权槽    | Direct-child state owned by `CliExecutor`; forced timeout leaves it until Core close/error releases it.                                                    |
| counterexample test          | 反例测试               | A permanent test proven to fail at its named fixed point; handler injection or a different phase is characterization.                                      |
| mutation-resistant test      | 抗突变测试             | A test shown to fail when the exact required ownership or cleanup transition is removed, so another guard cannot mask the regression.                      |
| canonical Archive identity   | 规范归档身份           | A client Archive `changeId` accepted only after the shared canonical entity guard, independently of strict-validation or skip-validation choices.          |
| planning-root archive        | 规划根归档             | An archived Change projected only from the current writable planning root; Launch-only and Reference content are excluded.                                 |
| task progress divergence     | 任务进度分歧           | A non-fatal difference between Apply literal-path counts and tracked-artifact-glob counts, shown with both sources intact.                                 |
| Spec Catalog                 | Spec 目录              | The shared live/static collection of owned and referenced Specs, indexed by source-aware compound identity.                                                |
| Spec identity                | Spec 复合身份          | `(owned, specId)` or `(referenced, storeId, specId)`; the source is part of identity because `specId` is not globally unique.                              |
| Owned Spec                   | 受控 Spec              | A writable Spec belonging to the one CLI-selected planning root, identified by `(owned, specId)`.                                                          |
| Referenced Spec              | 引用 Spec              | A direct read-only Spec projected from a declared Store through CLI list/show evidence, identified by `(referenced, storeId, specId)`.                     |
| Reference enumeration        | 引用 Spec 枚举         | Per-Store list projection from Doctor Store ids; failures retain evidence without deleting healthy results.                                                |
| Reference export policy      | 引用导出策略           | Explicit `include` or `omit` consent required before a static export may copy or deliberately exclude declared Reference Specs.                            |
| omission state               | 明确省略状态           | Static evidence that Reference content was deliberately excluded; it must not be rendered as if no References were declared.                               |
| CLI command evidence         | CLI 命令证据           | The inseparable process facts for one invocation: raw JSON, stdout, stderr, diagnostics, success, and exit status.                                         |
| typed CLI contract           | 强类型 CLI 合同        | A command-specific model whose known upstream fields are explicitly typed; passthrough unknown fields alone do not satisfy this contract.                  |
| explicit Store selector      | 显式 Store 选择器      | A caller-supplied `--store` value preserved by presence, including an empty invalid value that the CLI must reject rather than silently omit.              |
| workflow action intent       | 工作流动作意图         | The Update, Sync, Apply, or Archive instruction that must remain explicit when raw CLI evidence is wrapped into an Agent prompt.                           |
| executable contract fixture  | 可执行合同夹具         | A temporary real-root scenario that runs the pinned OpenSpec CLI and asserts payload plus process evidence, rather than matching source substrings.        |
| CLI-resolved path            | CLI 已解析路径         | An absolute planning, change, artifact, or context path returned by OpenSpec CLI; Agent and OPSX flows consume it instead of deriving paths from cwd.      |
| contract drift               | 合同漂移               | A CLI payload that executed but no longer contains required semantics; additive fields alone are not drift.                                                |
| self-reference               | 自引用                 | A Reference declaration resolving to the active root itself; OpenSpec omits it from the effective Reference index.                                         |
| empty healthy Store          | 空但健康的 Store       | A Store established by identity and config while optional specs/changes/archive directories are absent.                                                    |
| core profile                 | 核心工作流配置         | The exact upstream default workflow set; in OpenSpec 1.6 it is `propose, explore, apply, update, sync, archive`.                                           |
| scenario-loss protection     | 场景丢失保护           | Archive/spec-apply behavior that rejects a modified Requirement when it would silently remove existing Scenarios.                                          |
