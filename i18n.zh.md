# OpenSpecUI Chinese terminology

| English term                             | Canonical Chinese term   | Meaning                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| OpenSpec root                            | OpenSpec 规划根          | One writable `openspec/` planning tree selected for a command.                                                                                                                                                                                                                                                                             |
| project root                             | 项目规划根               | An OpenSpec root colocated with a code repository.                                                                                                                                                                                                                                                                                         |
| Store                                    | 规划仓库                 | A registered OpenSpec root with Store identity; normally standalone Git, but an existing nested root can be promoted without its own `.git`.                                                                                                                                                                                               |
| Store registry                           | 本机 Store 注册表        | Per-user/per-machine mapping from Store id to checkout path, shared across projects by default; its data root can be isolated with `XDG_DATA_HOME`.                                                                                                                                                                                        |
| declared Store                           | 外置规划指针             | A config-only code repository's `store:` declaration that redirects root selection.                                                                                                                                                                                                                                                        |
| Reference                                | 只读规划引用             | A declaration that adds another Store's specs to instructions without changing the writable root.                                                                                                                                                                                                                                          |
| Context                                  | 工作上下文               | The current root plus its available referenced Stores, derived from declarations.                                                                                                                                                                                                                                                          |
| Workset                                  | 个人工作集               | A local named set of folders opened together; it carries no planning semantics.                                                                                                                                                                                                                                                            |
| root selection                           | 规划根选择               | The ordered procedure that decides where a command acts.                                                                                                                                                                                                                                                                                   |
| multi-root planning                      | 多规划根协作             | Planning across independently owned roots without introducing a package graph.                                                                                                                                                                                                                                                             |
| OpenSpec data home                       | OpenSpec 用户数据根      | The single `${XDG_DATA_HOME}/openspec` tree containing Store registry, Worksets, and user schema overrides.                                                                                                                                                                                                                                |
| OpenSpec data scope                      | OpenSpec 数据域          | The runtime selection of one OpenSpec data home; scopes replace rather than overlay each other.                                                                                                                                                                                                                                            |
| OpenSpec config home                     | OpenSpec 配置根          | The separate XDG config location selected by `XDG_CONFIG_HOME` (or platform fallback); OpenSpec environment-global `config.json` lives here, not in the OpenSpec data home.                                                                                                                                                                |
| launch project                           | 启动项目                 | The code project used to start one OpenSpecUI backend session.                                                                                                                                                                                                                                                                             |
| Root Context                             | 根上下文                 | The shared reactive projection of launch project, CLI-selected planning root, direct References, CLI evidence, and inherited data scope.                                                                                                                                                                                                   |
| workflow target                          | 工作流目标               | The launch project, selected planning root, root source, Store id/selector, References, and root evidence fixed for one action.                                                                                                                                                                                                            |
| workflow action evidence                 | 工作流操作证据           | The command-specific Status or Instructions result retained with parsed data, raw output, paths, diagnostics, and exit status.                                                                                                                                                                                                             |
| workflow hook v2                         | 工作流 Hook v2           | The breaking hook contract whose context carries an explicit workflow target instead of ambiguous `projectDir`.                                                                                                                                                                                                                            |
| Root action gate                         | 根操作门禁               | The shared readiness rule that unlocks root-dependent actions only for a current ready Root Context.                                                                                                                                                                                                                                       |
| stale Root Context                       | 过期根上下文             | The last successful Root Context retained for display during refresh/failure; it is informative but cannot authorize a new action.                                                                                                                                                                                                         |
| Project Binding                          | 项目绑定                 | Launch-project `store:` and `references:` declarations plus the resulting Root Context preview; it does not own active-root schema/rules.                                                                                                                                                                                                  |
| Active Root Config                       | 当前规划根配置           | Schema, context, and rules stored in the CLI-selected writable planning root; an existing empty file remains distinct from an absent file.                                                                                                                                                                                                 |
| Environment Global Config                | 环境全局配置             | Profile, delivery, workflows, and other global settings read by `openspec config list --json` from the CLI-resolved OpenSpec config home; it is runtime-environment scoped, distinct from project config and `XDG_DATA_HOME`.                                                                                                              |
| Config readiness gate                    | 配置就绪门禁             | The shared Root Context gate that keeps Config root mutations locked during loading, stale refresh, transport failure, or CLI-owned error.                                                                                                                                                                                                 |
| shared Store consequence                 | 共享 Store 影响          | An objective notice that an external Store-backed root is observed by other projects resolving the same Store; it is not a machine-wide project inventory.                                                                                                                                                                                 |
| projection refresh lock                  | 投影刷新锁               | A loading lock that spans the asynchronous subscription rebind until the replacement CLI projection arrives.                                                                                                                                                                                                                               |
| Projection Work                          | 投影工作                 | One Server-owned, observable computation for a typed projection input; it owns identity, sharing, bounded caching, stages, batches, cancellation, invalidation, and terminal evidence without becoming a second fact source.                                                                                                               |
| Projection Work identity                 | 投影工作身份             | The complete cache/single-flight key: projection kind, Planning-root and Store provenance, owner generation or binding token, explicit selector, input fingerprint or invalidation generation, and protocol version.                                                                                                                       |
| single-flight projection                 | 单飞投影                 | Same-identity subscribers join one in-flight projection computation and receive independent lifecycle views; it does not permit a retired generation to publish into a newer one.                                                                                                                                                          |
| projection phase trace                   | 投影阶段轨迹             | Monotonic Server timing evidence for transport, Root readiness, cache hit/join/start, leaf settlement, first stable payload, completion, error, or cancellation. It is evidence, not UI state inferred from copy.                                                                                                                          |
| projection display snapshot              | 投影显示快照             | 最近一次已结算的类型化 CLI 投影及其来源证明，可为 current 或 stale-display-only。它不是文件解析结果；只有明确 current 的快照可参与读后校验授权。                                                                                                                                                                                           |
| reactive retained Pull                   | 响应式保留快照拉取       | A typed display read that returns bounded Server-retained/current projection state through the already-current reactive Root owner. It may expose stale-display-only data immediately, but it does not reacquire imperative command authority or rerun Doctor/Context.                                                                     |
| fresh Document admission                 | 新文档准入               | The first projection read by a newly created browser Document whose module-local cache is empty. On an existing Server it may consume retained state before replacement computation settles.                                                                                                                                               |
| cold computation                         | 冷计算                   | Projection computation after a fresh Server/runtime start with no reusable Root or business snapshot. Its latency includes CLI and Root warmup and must not be inferred from same-Server reload evidence.                                                                                                                                  |
| same-Server reload                       | 同服务端刷新             | A fresh browser Document opened against an already-running Server. It tests retained-state admission and client convergence separately from fresh-Server cold computation.                                                                                                                                                                 |
| authentication admission                 | 认证准入                 | A protected live bootstrap request completed before Project Web starts ordinary App transports. Success permits initialization; 401/403 settles an authentication terminal state without starting tRPC, WebSocket, or PTY retry loops.                                                                                                     |
| authentication terminal state            | 认证终态                 | An explicit document-level `authentication-required` result. It ends initial Loading while preserving the rejection as an error; it is not offline, current data, or silent transport retry.                                                                                                                                               |
| iframe capability delegation             | iframe 能力委派          | The App iframe's explicit Permissions Policy surface for the embedded Project Web. It grants only required features such as Clipboard read/write and does not imply backend authority or unrelated browser permissions.                                                                                                                    |
| observation-to-tab convergence           | 观测到标签收敛           | SessionTabs and iframe presentation committing the same accepted backend observation generation. A late checking/offline result cannot update only one presentation branch.                                                                                                                                                                |
| disconnect confirmation                  | 事件驱动断线确认         | Focus refresh, reconnect, and transport failure share one unresolved health probe per complete tab identity. Each consumer keeps its generation guard; HTTP success cannot fabricate Live during reconnect.                                                                                                                                |
| replacement observation join             | 替代观测合流             | After initial admission, explicit refresh and reconnect for one complete Hosted tab identity join before another generation is allocated. A refresh may promote a reconnect still probing health to perform Root refresh; distinct or replaced tabs never share the run.                                                                   |
| interaction-suite resource budget        | 交互测试套件资源预算     | A bounded suite-level execution allowance for a large jsdom interaction suite after exact-case replay proves workspace contention. It does not widen `waitFor`, transport, mutation, or user-visible lifecycle deadlines.                                                                                                                  |
| parent-inventory rebind                  | 父级清单重绑定           | Progressive observation that reads an existing parent inventory before subscribing to a newly present child. It avoids one watcher or poll per absent leaf while still converging when a deep directory creation is coalesced to a parent event.                                                                                           |
| missing-path ancestor settlement         | 缺失路径祖先结算         | A default-off watcher mode for a bounded missing logical target. A coalesced strict-ancestor creation event may wake the owner only while the target is absent; target-presence verification filters unrelated events, and normal exact subtree matching resumes after creation.                                                           |
| shell block-size budget                  | 壳层块轴预算             | The remaining vertical space assigned by App shell after fixed/sticky chrome. A nested Sessions surface consumes that space instead of declaring another viewport height.                                                                                                                                                                  |
| single inline scroll owner               | 单一横向滚动所有权       | The live Board lane grid is the only surface allowed to scroll horizontally when four lanes exceed available width; the route, shell, and lane sections contain inline overflow instead of creating competing scrollbars.                                                                                                                  |
| independent lane block scroll            | 列内独立纵向滚动         | Each live Kanban lane keeps its header outside a bounded row region that scrolls vertically on its own, so one long lane neither grows the page nor moves sibling lane headers.                                                                                                                                                            |
| focus refresh continuity                 | 焦点刷新连续性           | Focus/visibility revalidation that retains mounted Inspector content, selection, and component identity while replacement projection work settles. It is not a route remount or an authoritative empty reset.                                                                                                                              |
| stable selected read locator             | 稳定选中读取定位符       | The selected backend locator retained for display projection continuity while a replacement generation is pending. It grants no mutation authority; writes still require the current selected tab and observation generation.                                                                                                              |
| HTTP mutation admission projection       | HTTP 变更准入投影        | The exact backend-owned accepted mutation envelope displayed until the WebSocket ledger carries the same request. It is immediate operation evidence, not optimistic Store inventory or terminal success.                                                                                                                                  |
| SSG server entry contract                | SSG 服务端入口合同       | The deterministic machine-readable link from a clean SSG Server build to the exact renderer imported by export. A build-only pass does not prove this contract or the real CLI export path.                                                                                                                                                |
| bounded projection scheduler             | 有界投影调度器           | A resource-class scheduler that caps CLI, filesystem, Git, and CPU/Worker concurrency and gives foreground work priority over optional warmup.                                                                                                                                                                                             |
| demand planner                           | 按需规划器               | A projection planner that computes only the facts required by the requesting surface; low-priority Schema, Apply, and artifact work is separate from OPSX Status.                                                                                                                                                                          |
| independent projection                   | 独立投影                 | One separately owned asynchronous fact inside one page. Its loading, retained data, error, and empty conclusions must be derived from that owner only; a sibling projection cannot settle, hide, or relabel it.                                                                                                                            |
| Schema catalog/tab inventory             | Schema 目录/标签清单     | The Config-owned projection that supplies Schema tabs and their availability facts. Its loading, error, and empty state need a host outside individual Schema tabs, because those tabs do not exist while the inventory is absent or empty.                                                                                                |
| subscription lifecycle owner             | 订阅生命周期所有者       | The shared internal owner of cached snapshots, generation identity, retirement, and static-loader publication. It prevents a retired subscription generation from changing state or cache while preserving each public projection's distinct loading, updating, and authority semantics.                                                   |
| authoritative projection wait            | 权威投影等待             | A correctness-first wait while a route or action has stale/display data but no current subscription or Root-generation authority. It must not be presented as current success, but presentation need not discard usable stale content.                                                                                                     |
| navigation preparation wait              | 导航预取等待             | The bounded query/prefetch phase that currently runs before a detail View Transition commits route navigation; it improves transition continuity but directly adds perceived navigation latency.                                                                                                                                           |
| interaction phase sample                 | 交互阶段样本             | One bounded in-memory timing record from a single production coordinator. It measures named local phases but does not infer causality across independent subscriptions, Root resolution, or transports.                                                                                                                                    |
| latest navigation request                | 最新导航请求             | The newest requested navigation in one route area. It is request provenance, not proof of the current Router location or DOM; superseded attempts retain their own late-effect evidence without reclaiming this identity.                                                                                                                  |
| route update issued                      | 路由更新已发出           | The exact point at which the synchronous navigation update callback returns. A discarded Router navigation Promise means this fact does not prove Router completion or DOM commit.                                                                                                                                                         |
| artificial mount gate                    | 人工挂载门闩             | A local first-frame Loading state that observes no network, subscription, Router, View Transition, or data-readiness fact. Settings and Archive historically owned separate instances; remove each only at its route while retaining real loading, error, updating, and authority topology.                                                |
| first-render draft authority             | 首帧草稿权威             | When a current cached configuration is already available, writable local draft state initializes from that value before effects. A default draft that is corrected later cannot authorize an immediate Save.                                                                                                                               |
| field-value draft synchronization        | 字段值草稿同步           | A local draft follows an actual upstream field-value change, not replacement identity of the enclosing parsed Config object. Equal emissions preserve dirty local edits; changed fields replace only their corresponding drafts.                                                                                                           |
| projection updating signal               | 投影更新信号             | An explicit subscription lifecycle fact that a retained projection is being recomputed or rebound. A component-only mock of `data + isLoading` cannot substitute for a production signal from the shared subscription owner.                                                                                                               |
| realtime projection state topology       | 实时投影状态拓扑         | The eight presentation states: no-content `idle`, `initial-loading`, `empty`, `initial-error`; content `partial`, `current`, `revalidating`, `refresh-error`. Authority and cause remain separate facts.                                                                                                                                   |
| projection revalidation                  | 投影重验拉取             | 用户操作、文件触发、服务端失效通知、重连或 Root rebind 后，对同一幂等 CLI Work 发起或加入的更新。期间保留旧 CLI 快照并独立标记 revalidating；Push 是唤醒/生命周期事实，客户端 Pull 新投影。                                                                                                                                                |
| display-only action lock                 | 仅展示态操作锁           | Retained stale content remains readable, selectable, and copyable, while any action requiring a current projection stays locked until a current replacement arrives.                                                                                                                                                                       |
| visual lifecycle language                | 视觉生命周期语言         | A low-noise visual projection of normal lifecycle through stable geometry, luminance, and native motion. It avoids routine status copy but retains hidden accessible equivalents; empty, error, conflict, and block states keep concise text and actions.                                                                                  |
| revalidation coalescing window           | 重验合并窗口             | A bounded same-identity window that joins bursty invalidations into one client pull. User-triggered work and terminal state changes bypass it.                                                                                                                                                                                             |
| retained empty snapshot                  | 保留的空快照             | A previously observed empty projection kept visible while replacement truth is unresolved. It may carry Updating or error evidence, but cannot be labeled as the current empty result until recomputation settles.                                                                                                                         |
| workflow status unavailable              | 工作流状态不可用         | A settled or failed CLI Status projection with no current matching status for a rendered Change. It is distinct from initial loading and does not imply completion or archive readiness.                                                                                                                                                   |
| terminal transport error precedence      | 传输终态错误优先         | Page-presentation rule that a terminal transport error ends an unresolved Loading claim. It does not make retained data current or weaken the underlying authority gate.                                                                                                                                                                   |
| source-empty conclusion                  | 来源空结论               | A claim that one current source contains no entities, such as no Owned or Referenced Specs. Retained or absent data under transport failure cannot authorize this conclusion.                                                                                                                                                              |
| recompute-started                        | 重算已开始               | A subscription-local lifecycle event emitted after this ReactiveContext consumes a dependency wake and confirms it is not aborted, but before the replacement task executes. | reactive subscription retirement         | 响应式订阅清退           | Server-owned unsubscribe cleanup that aborts the underlying ReactiveContext stream and removes its tracked dependencies. | effective workflow default               | 有效工作流默认集         | The workflow set OpenSpec CLI applies from profile semantics; the core profile always uses the full core set regardless of raw `workflows` presence or content.                                                                                                                                                                            |
| config file presence                     | 配置文件存在性           | The explicit `exists` fact for a config file; it is independent from whether the file content is empty.                                                                                                                                                                                                                                    |
| Code repository                          | 代码仓库                 | The Git repository containing the launch project; it is the explicit default scope for project Git operations.                                                                                                                                                                                                                             |
