# Research plan — 1.16.1 rotation

## Mechanism

Nothing in our runtime reads these upstream changes; what changes is the CLI's **verdict** on authored
markdown, which we surface verbatim. The rotation therefore has two jobs: make the pinned identity
consistent with what is actually installed, and prove the new verdicts so a future regression in our
fixture matrix is visible.

## Slices

### S1 — identity rotation (serial, blocks everything)

`packages/core/package.json` alias → `1.16.1`; lockfile regenerated by `pnpm install`;
`PINNED_OPENSPEC_V16_VERSIONS = ['1.16.1']`; `PINNED_AGENT_GENERATOR_VERSION = '1.16.1'`; the 14
`official-cli-v16-*.test.ts` literals; `root-context-cold-start.integration.test.ts` ×2;
`w2-project-binding-playwright.ts`; `upstream-contract-regression.test.ts` `EXPECTED_COMMIT` →
`0fa4a9705c20ef1c571fe3ded74435733e4b73a1`; the `references/openspec` gitlink.

Falsifier: before the alias rotates, `--version` must print `1.16.0`, so any fixture that only passes
because it never asserted identity would be caught by `expectPinnedVersion`.

### S2 — executable proofs for the verdict changes

New fixture file `official-cli-v16-unrecognized-delta-section-fixtures.test.ts`:

1. **1.16.1**: a change delta whose requirement sits under `## Add Requirements` returns
   `level: 'ERROR'` from `validate --json`, and `validate --strict` fails.
2. **1.16.1**: the same requirement under `## Notes` stays `level: 'WARNING'` and plain validation
   stays valid (the escalation is scoped to headers that read as delta operations).
3. **1.16.1**: `archive` refuses the unrecognized-header shape with an error naming the requirement and
   the section, so the file is not silently merged.
4. **Boundary (1.15.0, retained alias)**: the same authored shape validates **without** an ERROR — the
   escalation is a 1.16-line fact, and the boundary proves it.

New fixture file `official-cli-v16-parser-acceptance-fixtures.test.ts`:

5. `### Requirement: Foo ###` and `## Requirements ##` are accepted on 1.16.1 (name normalizes to
   `Foo`), and a requirement inside an HTML comment is **not** reported as an orphan.

Falsifier for 5: on the same fixture, an _uncommented_ copy of the same requirement outside any delta
section is reported — so "nothing is reported" cannot pass for the wrong reason.

### S3 — docs and spec truth

`references/openspec-1.16.1-report.md` (done); spec delta rotating the pinned-fixture requirement and
adding the two proof requirements; `AGENTS.md` live pin + a dated 2026-11-07 decision line; changeset
(`@openspecui/core` patch, `openspecui` patch — the CLI bundles core, so the generator baseline change is
user-visible there).

## Risks

- **Literal drift**: 16 pre-existing `official-cli-v16-*.test.ts` files carry `1.16.0` in names, describes and assertions. A
  hard-empty gate is the wrong guard here — the sweep legitimately keeps the admission floor, the
  window range, in-window parse samples, captured decode payloads and historical provenance. The guard
  is therefore a classified sweep: `rg -n '1\.16\.0' packages/*/src scripts packages/web/scripts`,
  where every remaining hit must fall into one of the deliberate-keep kinds listed in CP1 and no hit may
  state the current pin. A missed assertion still passes against a rotated alias, so the sweep matters
  even though `expectPinnedVersion` catches identity.
- **A proof that passes for the wrong reason**: both new fixtures assert the _presence_ of the new
  verdict and, on the boundary, its absence.
- **The 1.15.0 alias is a boundary, not a subject**: it may only be used to prove absence.
