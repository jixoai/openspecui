## MODIFIED Requirements

### Requirement: Generator Evidence Follows the Admitted CLI

Generator staleness evidence SHALL follow the admitted OpenSpec CLI line: artifacts generated by the 1.16.0
pinned CLI baseline SHALL read as current for admitted 1.16.x sessions, artifacts generated by older lines
SHALL carry their historical generated-version evidence, and the pinned generator constant SHALL state the
1.16.0 baseline. A session running a retired CLI line SHALL NOT receive the v16 registry's staleness
interpretations for artifacts it did not generate.

#### Scenario: Live version is never fabricated

- **GIVEN** an Agent projection cannot resolve the running CLI version
- **WHEN** generator evidence is computed
- **THEN** the projection SHALL report unresolved evidence
- **AND** SHALL NOT present the pinned constant as the observed version

#### Scenario: Stale generated state is line-aware

- **GIVEN** on-disk Agent artifacts carry `generatedBy: 1.13.2` while the admitted CLI line is 1.16
- **WHEN** generator evidence is computed
- **THEN** the artifacts SHALL be reported as stale with the generator version as evidence
- **AND** artifacts generated by an admitted 1.16.x generator SHALL NOT be reported stale

#### Scenario: Staleness tracks the admitted line

- **GIVEN** Agent artifacts generated by the pinned 1.16.0 CLI in an admitted 1.16.x session
- **WHEN** tool init state is projected
- **THEN** the artifacts SHALL read current against the 1.16.0 pinned generator baseline
- **AND** artifacts generated by older lines SHALL retain their historical generated-version evidence and
  any staleness interpretation the admitted CLI owns
